# file-admin

The optional Probanda plugin that renames, moves and deletes the practitioner's own files. It holds `/housekeeping` (naming and filing a matter's loose files), `/route-accounting` (routing loose accounting files), `/file-sorting` (the folder profiles they use), `/file-apply` (the rename and move engine), the `housekeeping-namer` and `housekeeping-reviewer` agents, and the `files` server with its `file_ops__*` and `housekeeping__*` tools.

Disable it to keep Probanda away from your files. Every other Probanda plugin keeps working without it. A step elsewhere that would move or trash a file stops and says it needs `file-admin`. A deletion is still redirected to a recoverable trash by `practice`, and without `file-admin` it is refused.

The host's own shell (`device_bash` in Cowork, Bash/PowerShell elsewhere) can still create and rename files in a connected folder. That access is outside any plugin's control. Disabling file-admin removes Probanda's file tools, not the host's.

## What to install, and in what order

`file-admin` requires `practice`. Install `practice` first, then `file-admin`. Its skills call the `data` server and the `/file-naming` grammar that `practice` ships, so without `practice` those calls fail.

Not every host installs a required plugin for you, and a plugin whose required plugin is missing loads with tools and agents absent.

Everything in this folder is generated by `scripts/build_plugin.py` from the sources in the development repo: `.claude/skills/` and `source/file-admin/`. Never edit it by hand. Change the source and rebuild.
