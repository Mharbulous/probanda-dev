# Outgoing email

Read when: the practitioner asks to draft, prepare, publish, email, send or forward an email or anything else to anyone, from any skill or from none ("draft an email to all parties", "email it to opposing counsel", "send this to the client", "publish it"). "Publish" said of an email means this route's unsent `.eml`, presented for the practitioner to review, revise and send, never a hosted page or document. This file is the one source for that route. A skill that ends in an email adds only what its own Writing decides (recipients, subject, attachment) and cites this file for the rest.

**An email is never drafted in chat.** A request for an email is answered by writing its `.eml` by this route and presenting it as a file card. Under `/draft`, the `.eml` is written and shown before the email is saved as a Writing, and the save follows in the same turn (`/draft`'s SKILL.md, "An email request writes the `.eml` first"). No ingest is run or offered before the `.eml` is shown (`/draft`'s `references/letters.md`, "Ingestion check"). With no purpose stated, the body is left empty, never inferred from the file.

**The model never sends email.** Every outgoing email is an unsent draft that the practitioner opens, checks and sends from their own mail program (`docs/adr/0032`). Never load, call or dry-run a mail send, forward or reply tool to deliver one. A plugin hook refuses those calls and names this route. The one exception is `executive-assistant`'s automated morning briefing, which goes only to the practitioner's own address and is never correspondence.

**The route.** Call `drafting_forms__draft_harness` with `step` `write_email`. ToolSearch it. On a remote-device host its name carries the host's prefix. This route is the only author of a drafted `.eml`: never build one any other way, by a script, the Write tool or a mail library. Pass:

- `matter_root`: the matter folder, omitted for an email that belongs to no matter, whose draft then goes to `<case_data_root>\_practice\drafts\` and whose attachments must be absolute paths.
- The recipients, one of three ways. Never guess an address.
  - **All counsel of record** ("all counsel", "all parties", "the service list"): `to_service_list: true`, with `db_path` (the matter's drafting database) and, when the request names one, `proceeding_id`. The server reads counsel from case data and fills To and Cc itself.
  - **A saved Writing's recipients**: `filing_id` with `db_path`.
  - **Typed addresses**: `to` (at least one), address strings, `"Name <a@b>"` or `"a@b"`, as the practitioner gives them or from `/matter-data` or `/drafting-data`.

  `cc` adds address strings in every case. The firm's own people it copies on email to counsel (the firm profile's `cc_on_counsel_email`, set with `/practice-data` as the practitioner states the firm's practice) are added to Cc whenever the server addresses the email from case data. Never add one by inference. The result's `addressed` lists what was written and, in `not_addressed`, everyone left out for want of an email. Before presenting, ask `/matter-data` for each left-out party's `contact_info` and `replaced_representative`. With the draft, give a line for each one not reached, quoting any email in its notes. Offer only one given as the party's own or current counsel's, never a former lawyer's. Add it on the practitioner's word, as for a copying request, or in `to` after `no_recipients`, which lists them.
- `subject`: one line. The word DRAFT in capitals marks an email whose facts are not all checked (`/draft`'s SKILL.md ban 20).
- `body`: plain text, the message only. Omit it for a blank draft. Its words come from the `lawyer:scrivener` agent or from the practitioner's dictation, never from the calling context (`shared/correspondence-isolation.md`). The one exception is `executive-assistant`'s morning briefing to the practitioner, which is not correspondence. **The body carries no closing and no name.** The signature supplies them.
- `output_name`: a bare stem under `/file-naming`'s grammar, dated the day it is written. Optional `folder`: one folder name under the matter's `0. DRAFT` folder.
- `attachments`: PC paths, absolute or relative to the matter folder. Copy a container-only file to the PC with `device_commit_files` first. Never attach a file ending ` UNSIGNED.pdf` unless the practitioner names it.

**From and signature.** The practitioner's email signature belongs in every draft. Probanda's restraint about signing documents does not apply to it, because the practitioner's own act is clicking Send. The server sets the From address from this machine's roster entry. It adds the signature from the roster person's template, `<case_data_root>\_practice\firm\email-signatures\<roster key>.htm` (`/practice-data`), when one exists. Otherwise it adds Outlook's default new-message signature for that address. The result's `signature_source` says which (`template`, `outlook` or null). When `signature` is null, quote its `signature_note` in one line. Then write the draft again with the roster entry's `closing` and `name` (`/practice-data`'s firm profile) at the end of `body`.

**Refusals**, each quoted in one line: `from_unresolved` (this machine's roster entry has no person or email: `/practice-data`), `attachment_unresolved` (names each file not found), `no_recipients` (case data holds no email for anyone it would go to), `bcc_unsupported` (the saved Writing has a blind copy, which this route cannot write) and `signoff_duplicates_signature` (remove the closing and name from `body` and call again).

**A counsel's copying request.** Before presenting an email to another party's counsel, make one `mail__search_emails` (ToolSearch it) per counsel: `from` their address, `body` "copy". Read a hit only for a request to copy someone and that address. With the draft, quote each request (`/show-me`) and failed search, and name each counsel with none found. On the practitioner's word, write the next " vN" with the address in `cc`, and name each address added.

**Present.** Present the draft, at the result's `path`, and then each file passed in `attachments`, in the order passed, as file cards in one call (`shared/present-files.md`). Every presentation of a draft with attachments carries them all. Give its PC path from the result, and tell the practitioner to open it, check it and send it from their mail program. Nothing is overwritten: a taken name gets the next " vN", reported as `versioned_from`. The draft is never the copy as sent. The sent message is filed with the matter's correspondence.
