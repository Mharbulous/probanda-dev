# file-manager

The optional Probanda plugin that renames, moves, changes and deletes files on the practitioner's computer that Probanda did not create. It holds `/housekeeping` (naming and filing a matter's loose files), `/route-accounting` (routing loose accounting files), `/file-sorting` (the folder profiles they use), `/file-apply` (the rename and move engine), the `housekeeping-namer` and `housekeeping-reviewer` agents, and the `files` server with its `file_ops__*` and `housekeeping__*` tools.

Without it, Probanda cannot rename, move, change or delete any file it did not create: it only reads or copies them. Disable it to keep Probanda's hands off your files. Every other Probanda plugin keeps working without it. A step elsewhere that would rename, move or trash such a file stops and says it needs `file-manager`, and a shell delete outside a Git worktree is refused, pointing to `file_ops__trash`. A step that only needs a file's content copies it and leaves the original where it was.

The host's own shell (`device_bash` in Cowork, Bash/PowerShell elsewhere) can still create and rename files in a connected folder. That access is outside any plugin's control. Disabling file-manager removes Probanda's file tools and the steps that use them, not the host's own tools.

## What to install, and in what order

`file-manager` requires `practice`. Install `practice` first, then `file-manager`. Its skills call the `data` server and the `/file-naming` grammar that `practice` ships, so without `practice` those calls fail.

Not every host installs a required plugin for you, and a plugin whose required plugin is missing loads with tools and agents absent.

Everything in this folder is generated by `scripts/build_plugin.py` from the sources in the development repo: `.claude/skills/` and `source/file-manager/`. Never edit it by hand. Change the source and rebuild.
