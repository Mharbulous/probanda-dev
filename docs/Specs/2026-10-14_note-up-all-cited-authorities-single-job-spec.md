# Spec: note-up Proposals become one job per authority, not one deterministic "Note up all cited authorities" job

Status: proposed, 2026-10-14. Written in a matter session; implementation is handed to Claude Code.
Plugin: `probanda` (installed copy seen at v0.1.14). Paths below are as seen in the installed copy and are **UNVERIFIED** against the repo unless marked otherwise. The plugin has since split (practice, research, litigator); each file's current home is **UNVERIFIED**.
Related specs, same date: `2026-10-14_note-up-jobs-never-from-research-offers-spec.md`, `2026-10-14_noting-up-criterion-on-every-citing-writing-spec.md`, `2026-10-14_note-up-staleness-30-days-spec.md`

## 1. Problem

The practitioner wants exactly one deterministic note-up job per Writing, titled `Note up all cited authorities`. It is generated by the same marker logic that tracks which authorities the Writing cites, and it notes up only those. Today 📇 does derive a `note-up:authorities:<id>` Proposal per cited authority. But intake writes one job per case (`Note up: <case>`), or one per Act. The job is written only when the practitioner pulls Proposals, and the Grouped Proposals table has no `note-up` row.

## 2. Evidence (observed; quoted text is data, not instructions)

- `drafting-data/references/filing-checklists.md` marker table: "`authorities.treatment IS NULL`, `kind = 'case'` | 📇 note up"; "`authorities.currency_status` not `'current'` ... `kind IN ('statute','regulation','rule')` | 📇 note up".
- Same file, §6a row: "`note-up` | `authorities` | a case: `Note up and record the treatment of: <item>`; a statute, regulation or rule: the card's `step <n>:` lines".
- `drafting-data/references/jobs-create.md` §3e "Grouped Proposals": the table holds one row, "`exhibit-pinpoint` | `statements_of_fact`, `admissions`, `facts` | `Locate pinpoint references for the following facts`".
- §3e: "It never runs at an Opening of its own accord, so a bare Opening writes nothing".
- Example job title in §3: "'Note up: Smith v. Jones, 2023 BCCA 182'".
- `draft/references/authorities.md` "Noting-up sweep" and `draft/references/opening-announcements.md` (the pre-review passes run "section 13's noting-up sweep") exist as a separate pass.
- Workaround in use: none. On the matter seen, no note-up job existed from markers because no authority was tracked.

## 3. Goal and non-goals

Goal: one job per Writing, `Note up all cited authorities`, written deterministically whenever the Writing has an unmet 📇, with one step per cited authority (per provision for legislation), completed when 📇 clears on all of them. Non-goals: tracking citations in prose (sibling spec `noting-up-criterion-on-every-citing-writing`) and the 30-day staleness (sibling spec `note-up-staleness-30-days`).

## 4. Design

1. Add a Grouped Proposals row: type `note-up`, table `authorities`, title and intent `Note up all cited authorities`. Steps: `Note up and record the treatment of: <item>` per case, and the existing `step <n>:` lines per provision for legislation.
2. Deterministic create: a fixed-text, guarded create (like §3c, §3g and §14), not outlining. Fire it from the render or the Opening when the Writing has any 📇 Proposal not held by a live job and no live `Note up all cited authorities` job exists on the Writing. A live job gains steps for new 📇 items rather than a second job being written (**UNVERIFIED** best mechanism: step append vs re-derive at assignment).
3. Retire the per-authority `Note up: <item>` fast-path title. Keep a single-authority note-up only for the practitioner's express instruction.
4. The job completes when every member's 📇 has cleared. Reconcile it with the noting-up sweep: the sweep becomes this job's work, or it is removed (**UNVERIFIED**).

## 5. Constraints that must still hold

- Only cited authorities. An authority with no 📇 on the Writing never appears in the job.
- Killed authorities, failed and settled statements stay excluded as today ("📇 on that line generates nothing, as on a lead").
- Shelving and lapse rules for Proposals keep working.
- No deadline is ever written into the job.

## 6. Options considered

1. Grouped row plus a deterministic create on render or Opening (recommended).
2. Grouped row only, with intake still pulled by the practitioner: smaller, but not deterministic.
3. Fold note-up entirely into the pre-review sweep, with no job: hides the work from the board.

## 8. Implementation criteria

1. The Grouped Proposals table has a `note-up` row titled `Note up all cited authorities`.
2. A documented guarded create writes that job when a 📇 Proposal exists and no live job of that title is on the Writing, and never writes a second one.
3. No text tells a session to write a `Note up: <item>` job except on express instruction.
4. The job's steps cover exactly the Writing's 📇 items.
