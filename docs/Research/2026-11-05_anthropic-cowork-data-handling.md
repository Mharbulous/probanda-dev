# Anthropic data handling in Cowork, Claude Code cloud sessions and artifacts

Research for Probanda's privacy promises to lawyers about client information. Facts only, each with a source URL. No decision or recommendation is made here. All sources are Anthropic-owned pages fetched on 2026-11-05. Canadian privacy law, Law Society of BC cloud guidance and data-location rules are covered in `2026-10-15_privacy-law-and-data-location.md` and are not repeated here.

Method note: pages were read through a fetch tool that returns short verbatim excerpts. Text in quotation marks is verbatim from the page. Text outside quotation marks is a summary of the page. Most support.claude.com pages show only "Updated this week" (or "Updated today") instead of a calendar date. That is recorded as "no date shown".

## Summary: the hypotheses

| # | Hypothesis (observed in a Cowork session on 2026-11-05) | Finding |
|---|---|---|
| H1 | The model runs in Anthropic's cloud. | **Confirmed.** Cowork sessions run in the cloud by default, with the agent loop and code execution on Anthropic's servers (1.1). |
| H2 | Cowork changed in 2026 from running locally to running in the cloud. | **Confirmed, with a plan qualifier.** On October 6, 2026, new Cowork tasks on Pro, Max and Ultra plans moved to the cloud, with no way back. Tasks started locally before that date stay local. Local mode remains for "existing desktop deployments", and HIPAA-configured Enterprise organizations use Cowork (local mode). The Desktop changelog shows cloud Cowork sessions and a staged move of scheduled tasks and projects to the cloud already under way in September 2026 (1.2). |
| H3 | Probanda's tools run on the user's computer through a bridge. | **Not documented, and in tension with the docs.** The architecture overview states "Local MCP servers don't run in sessions in the cloud." The plugin support table says a plugin's local MCP server "Loads when the Cowork session runs on your computer." The docs describe a cloud session reaching the device through Claude Desktop only for connected folders (desktop file tools), the browser and computer use. No page found describes a cloud session calling a plugin's local MCP server through the desktop app (1.4). |
| H4 | Files edited through the bridge's shell change on the user's disk directly. | **Partly documented.** Cloud docs say "Your folders stay on your computer" and that Claude can "read from and write to your local files without manual uploads or downloads" in connected folders. In local mode and on 3P, Anthropic documents the connected folder as mounted so writes go to disk. No page describes a shell running on the user's computer in a cloud session. The docs say shell commands in a cloud session run in the cloud sandbox (1.3, 1.4). |
| H5 | A file is copied up to the cloud only to be viewed or processed with cloud-only tools. | **Refuted as stated.** The docs say the agent's work, "including any local files it opens through the desktop app, is processed on Anthropic's servers rather than staying on the device." Any file content Claude reads through the desktop app therefore reaches Anthropic's servers as part of the session. Separately, "When a task needs a file in the cloud, Claude fetches a copy of just that file," and those copies are deleted with the session. The docs do not limit copying to viewing or cloud-only tools (1.3). |
| H6 | An unconnected folder is unreachable. | **Confirmed.** "Claude can only read and write files in folders you've connected." Access also needs the desktop app open and online (1.3). |

Short answers to the four questions:

1. **Cowork.** Runs in Anthropic's cloud by default since 2026 (October 6 for Pro, Max and Ultra). Local files are not bulk-uploaded. Files Claude opens are processed on Anthropic's servers, and copies it fetches are stored with the session. Sessions and files are saved to the Claude account. Deleted tasks leave Anthropic's back end within 30 days. Consumer data trains models only if the "Help improve our AI models" setting is on. Team and Enterprise data is not used for training. Access is limited to folders connected through Claude Desktop while it is open.
2. **Claude Code cloud and Remote Control.** Cloud sessions run in Anthropic VMs. The repository is cloned or uploaded into the VM, and Anthropic stores the transcript. Remote Control runs on the user's machine, but the transcript, "including your messages, Claude's responses, and tool activity", is stored on Anthropic servers while connected. Both follow the account's retention policy.
3. **Artifacts.** Content is stored on Anthropic-operated infrastructure. Artifacts start private, can be shared within an organization or publicly, and can store up to 20 MB of text data. Enterprise owners can set artifact retention. No retention period is published for consumer artifacts.
4. **Plans.** Consumer: 30 days, or 5 years de-identified if training is on. Commercial: no training, 30-day standard deletion window after a user deletes. ZDR is Enterprise-only, covers Claude Code inference only, does not cover Cowork, and disables cloud sessions, Remote Control and artifacts. Stored data is in the US. Inference may be routed to the US, Europe, Asia and Australia unless the organization is on usage-based Enterprise with US-only inference.

## 1. Claude Cowork

### 1.1 Where the session and sandbox run

- "Cowork sessions run in the cloud by default: the agent loop and code execution run on Anthropic's servers" and "sessions and files are saved to the member's Claude account." In the cloud, "the agent loop and code execution run in an isolated, temporary sandbox on Anthropic-managed infrastructure". "Each session gets its own sandbox, created when the session starts and destroyed when it ends", and "This infrastructure is kept separate from Anthropic's corporate, research, and model-training environments." In local mode, "The agent loop runs natively on the device" and "Shell commands and any code Claude writes execute inside a dedicated Linux VM". "Local execution remains available for existing desktop deployments". Source: Claude Cowork architecture overview, https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview (no date shown).
- "Cowork runs your tasks in the cloud." "Claude's work runs on Anthropic's servers, in an isolated environment," and "Shell commands and code Claude writes run inside that environment." "Sessions keep running even when the desktop app is closed or your computer is asleep." Source: Get started with Claude Cowork, https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork (no date shown).
- "Cowork sessions run in the cloud on Anthropic's servers". The environment "can't reach your home or company network" and "is removed when the session ends". Source: Use Claude Cowork safely, https://support.claude.com/en/articles/13364135-use-claude-cowork-safely (no date shown).
- Enterprise (unified experience): "Each conversation that needs one gets its own virtual machine, managed by Anthropic." After a few idle minutes, "its disk is saved as an encrypted snapshot". "The sandbox environment expires 30 days after it was created." Source: Set up and manage the new unified Claude experience for your Enterprise organization, https://support.claude.com/en/articles/17444462-set-up-and-manage-the-new-unified-claude-experience-for-your-enterprise-organization (shows "Updated today").
- Local mode, HIPAA configuration: "'(local mode)' means a local session, not a session that runs in the cloud." "Cowork runs shell commands in a virtual machine (VM) on the member's computer." "Cowork runs Claude Code on the member's computer". Source: Set up Cowork (local mode) for a HIPAA-ready organization, https://claude.com/docs/cowork/hipaa-setup (no date shown).

### 1.2 The 2026 change from local to cloud

- "On October 6, 2026, new Cowork tasks on Pro, Max, and Ultra plans run in the cloud." "There's nothing to set up, and you can't switch back." "The Only on your computer option in Settings > General was removed." Users still set to local are moved: "you're moved to the cloud the next time you open the desktop app." "There's no setting to choose where a task runs on Pro, Max, and Ultra plans." Tasks started on the computer before the change stay there. Source: Use Claude Cowork on web, desktop, and mobile, https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile (no date shown).
- "On Pro, Max, and Ultra plans, new tasks you start on desktop run in the cloud too", while "tasks you started on your computer before October 6 keep running there". Source: https://support.claude.com/en/articles/13364135-use-claude-cowork-safely.
- For Pro, Max and Ultra, local mode applies only to tasks and scheduled tasks started on the device before October 6, 2026 (summary). Source: https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview.
- Claude Desktop changelog, https://claude.com/docs/cowork/changelog (covers at least 2026-08-13 to 2026-11-05 in the parts read):
  - v1.52386.3 (2026-09-11): "Changed the automatic move of scheduled tasks to the cloud, for accounts where it has started" and "Fixed two problems with local projects that are moving to claude.ai, for accounts where that move has started".
  - Known issue, 2026-09-10: "This affects Cowork on third-party inference deployments and Cowork sessions that run on your computer rather than in the cloud. Cloud sessions and Claude Code, including the Code tab, are not affected."
  - v2.37337.1 (2026-10-13): "Fixed Cowork tasks on a computer whose administrator turned off the local VM trying to start on that computer instead of in the cloud."
  - v4.16336.0 (2026-11-03): "Changed Reset App Data to also delete the signed-in account's Cowork tasks from Anthropic servers before it resets".
  - No changelog entry read announces the first release of cloud Cowork. The last ~69,000 characters of the changelog (entries before 2026-08-13) were not read.
- Enterprise: the unified experience "is off by default in existing organizations and turns on by default on November 16, 2026" (summary). Source: https://support.claude.com/en/articles/17444462-set-up-and-manage-the-new-unified-claude-experience-for-your-enterprise-organization.

### 1.3 Local files: connection, upload and copies

- "Your folders stay on your computer." "Claude reaches only the folders you've connected, through the desktop app, and only while it's open." "When a task needs a file in the cloud, Claude fetches a copy of just that file." "If the app is closed, the session keeps running but can't reach your local files." "When you delete a session, the copies Claude fetched are deleted too." Source: https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile.
- "Local file access is limited to folders the member has connected on the desktop" and "each local tool call is checked against the member's permissions before it runs." When a cloud session needs something on the device, "the request goes through the Claude Desktop app on that device over an Anthropic-brokered connection." "If the desktop app is offline, a session in the cloud can't reach the device." "Because a session in the cloud runs on Anthropic's servers", "the agent's work, including any local files it opens through the desktop app, is processed on Anthropic's servers" "rather than staying on the device." Source: https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview.
- "Claude reaches your computer through the Claude Desktop app, and only for the folders you've connected". "connecting local folders makes them reachable from a session in the cloud". Data "is processed on Anthropic's servers rather than staying on your computer". Source: https://support.claude.com/en/articles/13364135-use-claude-cowork-safely.
- "On desktop, Claude can read from and write to your local files without manual uploads or downloads." "Claude can only read and write files in folders you've connected," Source: https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork.
- "Cowork requires your explicit permission before permanently deleting any files." Source: https://support.claude.com/en/articles/13364135-use-claude-cowork-safely.

### 1.4 Local tools, MCP servers and plugins

- "Local MCP servers don't run in sessions in the cloud." "With local MCP servers disabled on a managed device, only the folder-limited desktop file tools remain available to sessions in the cloud." "Connector authorization tokens never enter the sandbox; connector calls are made on the server side." "The sandbox holds only session-scoped tokens that expire within hours." Source: https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview.
- Plugin component table, Cowork column, for "Local MCP server, a command the app starts, including `.mcpb` bundles": "Loads when the Cowork session runs on your computer". Source: Plugin feature support across platforms, https://claude.com/docs/plugins/platform-support (no date shown).
- "Plugins may include local MCP servers that run on your computer with the same permissions as any other program you run." "A plugin's local MCP server runs in Cowork and Claude Code, not in chat." "In Cowork, connectors reach external services through Anthropic's cloud, not through your local network." Source: Use plugins in Claude, https://support.claude.com/en/articles/13837440-use-plugins-in-claude (no date shown).
- "These capabilities reach things on your computer, so they need the app even though your session runs in the cloud." (local file access, browser use, computer use). Source: https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork.

### 1.5 What is stored, where, and for how long

- "your sessions and files live with your Claude account and follow you across desktop, web, and mobile." Deletion: "Your Cowork task will be removed from your task history immediately," "deleted from our backend storage systems within 30 days," "in accordance with our data retention periods." Source: https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork.
- "Every stored record is scoped to your organization and account." "Cowork via Claude, Claude Desktop, and Claude Mobile is captured in Compliance API." The page states no retention period, encryption detail or storage location beyond "Anthropic's servers". Source: https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview.
- Enterprise: "Conversations are kept until the member deletes them or according to your organization's custom data retention setting". Cowork cloud sessions a member starts directly are "kept until the member deletes them" and are not covered by custom retention (summary). Most files Claude gives in conversations on or after October 8, 2026 are deleted with their conversation (summary). Source: https://support.claude.com/en/articles/17444462-set-up-and-manage-the-new-unified-claude-experience-for-your-enterprise-organization.
- Local mode: "Cowork (local mode) stores task data on each member's computer. Securing and deleting that data is your organization's responsibility." Task folders hold "the task's transcript, uploaded files, and outputs". "Folders a member connects to a task" hold "The member's own files, including any that Claude created or changed there". Source: https://claude.com/docs/cowork/hipaa-setup.
- Local and 3P session audit log: it holds "Tool inputs and results, such as the text of a file that Claude reads or writes", and "the app doesn't send the file off the device". Source: User identity and local data (Claude Desktop on 3P), https://claude.com/docs/cowork/3p/data-storage (no date shown). This page describes 3P deployments, where "Conversation content leaves the device only as inference requests to your configured provider" and the other listed routes. It does not describe standard Anthropic-account Cowork.

## 2. Claude Code cloud sessions and Remote Control

### 2.1 Cloud sessions (claude.ai/code, Desktop "Cloud" environments, `claude --cloud`)

- "A cloud session is a Claude Code session that runs on cloud infrastructure instead of on your machine. By default it runs on infrastructure Anthropic manages". "each session runs in an isolated, Anthropic-managed VM." Source: Use Claude Code in the cloud, https://code.claude.com/docs/en/claude-code-on-the-web (no date shown).
- Upload: "The cloud VM clones your current directory's GitHub remote at your current branch, not your local checkout". Without a usable GitHub remote, "Claude Code bundles your local repository and uploads it directly to the cloud session." "For a full clone, the bundle includes your repository history across all branches, plus uncommitted changes to tracked files." On macOS, Linux and WSL, uncommitted changes to credential-like files are left out. On "Native Windows: uncommitted changes to tracked files upload as they are, whatever the file's name." "Untracked files are not included". Source: same page.
- Credentials: "your GitHub credentials stay encrypted on Anthropic's servers and never enter a session's VM." Network: "When running with network access disabled, Claude Code can still communicate with the Anthropic API, which may allow data to exit the VM." Source: same page.
- Storage and deletion: "Deleting a session permanently removes the session and its data. This action can't be undone." Idle VMs: "Cloud sessions stop after a period of inactivity and the session's VM is reclaimed"; on reopening, conversation history is restored. Source: same page.
- Sharing: on Pro, Max and Ultra, "Public visibility makes the session visible to any user logged into claude.ai"; on Team and Enterprise, "Team visibility makes the session visible to other members of your claude.ai organization". Source: same page.
- "Your repository is cloned into the session's isolated VM. Anthropic stores the session transcript so you can return to the session later. Code and session data are subject to the retention and usage policies for your account type". "All outbound traffic goes through a security proxy for audit logging and abuse prevention". "Prompts, code changes, and outputs follow the same data policies as local Claude Code usage". "for remote Claude Code, Claude accesses the repository where you initiate your Claude Code session." Source: Data usage, https://code.claude.com/docs/en/data-usage (no date shown).
- Restrictions: "Organizations with Zero Data Retention enabled, or with the HIPAA configuration applied, can't use `/web-setup` or other cloud session features. Organizations that use customer-managed encryption keys (CMEK) can't start cloud sessions either." Source: https://code.claude.com/docs/en/claude-code-on-the-web.

### 2.2 Remote Control (local session steered from claude.ai or the app)

- "When you start a Remote Control session on your machine, Claude keeps running locally the entire time, so your code execution and filesystem access stay on your machine." "your filesystem, MCP servers, tools, and project configuration all stay available". Files sent from phone or browser: "Claude Code downloads other files to your machine and passes them to Claude as `@` file references." Source: Remote Control, https://code.claude.com/docs/en/remote-control (no date shown).
- "While Remote Control is connected, the session transcript, including your messages, Claude's responses, and tool activity, is stored on Anthropic servers. The stored transcript keeps the conversation in sync across your devices and lets the session reconnect after a network drop. Execution and filesystem access stay on your machine, and stored transcripts are retained under the Data usage policy." "Organizations with Zero Data Retention enabled, or with the HIPAA configuration applied, can't enable Remote Control." Source: same page, section "Connection and security".
- "Remote Control sessions follow the local data flow since all execution happens on your machine; while connected, the session transcript is also stored on Anthropic servers to sync the conversation across devices". Source: https://code.claude.com/docs/en/data-usage.

### 2.3 Local Claude Code (for comparison)

- "Claude Code runs locally. To interact with the LLM, Claude Code sends data over the network. This data includes all user prompts and model outputs, encrypted in transit via TLS 1.2+." Anthropic API encryption at rest: "Infrastructure-level disk encryption (AES-256)." "Claude Code clients store session transcripts locally in plaintext under `~/.claude/projects/` for 30 days by default". Source: https://code.claude.com/docs/en/data-usage.
- Tool results go to Anthropic as part of the conversation, because the model runs on Anthropic's API. The "Data usage" page states that prompts and model outputs are sent. It does not use the words "tool results" for local Claude Code (see Not documented).

## 3. Artifacts

- Claude Code artifacts: "An artifact is a live, interactive web page that Claude Code publishes from your session to a private URL on claude.ai." "Claude builds the page from anything your session can reach, including your codebase and data it pulls through your connected tools". "A new artifact is visible only to you." On Team and Enterprise, sharing is to specific people or everyone in the organization. "Publicly: share a link that anyone on the internet can open, with no claude.ai sign-in required. On Team and Enterprise plans, public sharing is off until an Owner enables it". "Artifact content is stored on Anthropic-operated infrastructure and is visible only to authenticated members of the publishing organization and the people they share it with, unless the artifact is shared publicly." Retention: Owners can set "separate retention periods for artifacts that are still private to their author and artifacts that have been shared." Deletion with `/artifacts` "permanently deletes an artifact you own after you confirm. Its link stops working for everyone". Availability excludes organizations with "Customer-managed encryption keys (CMEK), HIPAA, and Zero Data Retention". Connector-backed pages: "each call runs through the viewing account's own connection", and "Local MCP servers you configure in Claude Code ... can supply data while Claude builds the page, but the published page can't call them." Source: Share session output as artifacts, https://code.claude.com/docs/en/artifacts (no date shown).
- claude.ai artifacts: "Everything you make is saved to the Artifacts tab in your Claude sidebar". "Artifacts can store data between sessions". Storage "accepts text only, no images, files, or binary data," and "Storage has a 20 MB limit per artifact." "Artifacts start private to you." Shared storage: "Claude shows a confirmation explaining that your data will be visible to others using it." For legacy artifacts, "unpublishing a legacy artifact permanently deletes all its stored data." No general retention period is stated. Source: What are artifacts and how do I use them, https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them (no date shown).
- Enterprise custom retention: "Custom retention periods apply to content in chats, projects, and artifacts." "A retention period that covers artifacts doesn't delete artifacts published with a public link." Source: Configure custom data retention controls for Enterprise plans, https://privacy.claude.com/en/articles/10440198-configure-custom-data-retention-controls-for-enterprise-plans (no date shown).
- ZDR: Artifacts are disabled because they require "storing published page content on Anthropic-operated infrastructure." Source: https://code.claude.com/docs/en/zero-data-retention.
- Local mode: artifacts are written to the Cowork files folder (`~/Claude` by default), which Claude Desktop does not delete automatically. Source: https://claude.com/docs/cowork/hipaa-setup.

## 4. Plans, terms, ZDR and region

### 4.1 Training

- Consumer terms: Anthropic may use Materials "including training our models, unless you opt out of training through your account settings." "Even if you opt out, we will use Materials for model training when:" the user gives Feedback or Materials are flagged for safety review (summary of the two conditions). Source: Consumer Terms, https://www.anthropic.com/legal/consumer-terms (effective Oct 8, 2025, as served).
- Consumer privacy center: data may be used if "You choose to allow us to use your chats and coding sessions to improve Claude", if "Your conversations are flagged for safety review", or on explicit opt-in. Scope: "the entire related conversation". "It does not include raw content from connectors (e.g. Google Drive), including remote and local MCP servers", unless content is "directly copied into your conversation with Claude." Source: Is my data used for model training? (consumer), https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training (last updated March 16, 2026).
- Commercial terms: "Anthropic may not train models on Customer Content from Services." "Customer Content is Customer's Confidential Information." "Data submitted through the Services will be processed in accordance with the Anthropic Data Processing Addendum". Source: Commercial Terms of Service, https://www.anthropic.com/legal/commercial-terms (effective June 17, 2025, as served).
- Claude Code: "We will train new models using data from Free, Pro, Max, and Ultra accounts when this setting is on (including when you use Claude Code from these accounts)." Commercial: "Anthropic does not train generative models using code or prompts sent to Claude Code under commercial terms, unless the customer has chosen to provide their data". Source: https://code.claude.com/docs/en/data-usage.
- Commercial feedback: "If you explicitly report feedback or bugs to us (e.g. via our thumbs up/down feedback button)" "or otherwise choose to allow us to use your data, then we may use your chats and coding sessions to train our models." Source: Is my data used for model training? (commercial), https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training (last updated August 18, 2026).

### 4.2 Retention

- Consumer (Free, Pro, Max, and Claude Code on those plans): deleted conversations are "Deleted from our back-end storage systems within 30 days." With training on, "we may retain your data in a de-identified format for up to 5 years in our model training pipelines." Flagged: "We retain inputs and outputs for up to 2 years and trust and safety classification scores for up to 7 years." Feedback: "we retain data associated with that submission for 5 years." Source: How long do you store my data?, https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data (last updated July 1, 2026).
- Commercial: API inputs and outputs are deleted "within 30 days of receipt or generation". For Claude for Work, Enterprise and Console, "we retain your chats and coding sessions in the product to provide you with a consistent product experience", and deleted chats are "Deleted from our back-end storage systems within 30 days." Same 2-year and 7-year flagged-content rule. Source: How long do you store my organization's data?, https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data (last updated July 1, 2026).
- Claude Code: consumer "5-year retention period" with training on, "30-day retention period" with it off. Commercial "Standard: 30-day retention period". Source: https://code.claude.com/docs/en/data-usage.
- Enterprise custom retention: "The minimum retention period is 30 days". "By default, data is retained indefinitely unless a custom retention period is set." Custom periods do not apply to "any other feature that runs Claude Code in the cloud", but "Cloud sessions Claude starts from a chat are deleted with that chat." Source: https://privacy.claude.com/en/articles/10440198-configure-custom-data-retention-controls-for-enterprise-plans.
- Covered Models: "Prompts submitted to, and outputs generated by, covered models are retained for 30 days." Covered models are "Mythos-class models and future models with similar capabilities that we designate as covered models." "Claude chat and Cowork through Claude for Enterprise already use standard retention, so they are not affected" (summary). Source: Data retention practices for Covered Models, https://support.claude.com/en/articles/15425996-data-retention-practices-for-covered-models (no date shown, effective June 9, 2026). The ZDR page states that Claude Fable 5.1 and Fable 5 "are Covered Models that require data retention by default". The Covered Models article, as read, does not name Fable as a covered model. These two pages disagree.
- Privacy Policy: it "does not apply to content that we process on behalf of customers of our business offerings". Canadian disclosures: personal data "may be transferred or disclosed to other jurisdictions for processing and storage outside of Canada," including the United States. Source: Privacy Policy, https://www.anthropic.com/legal/privacy (effective Sep 10, 2026).

### 4.3 Zero Data Retention

- "Zero Data Retention (ZDR) for Claude Code is available to qualified accounts on Claude for Enterprise." "ZDR is not included in the standard Claude for Enterprise plan and cannot be enabled from your admin settings." "ZDR covers Claude Code inference on Claude for Enterprise." Not covered: "Cowork sessions are not covered by ZDR." Also not covered: Chat on claude.ai, and "Data processed by third-party tools, MCP servers, or other external integrations". Disabled under ZDR: cloud sessions ("Requires server-side storage of session data, including conversation history with prompts and completions"), Chat and Cowork unified, Claude Tag, Artifacts, feedback submission and Remote Control. "If a session is flagged for a policy violation, Anthropic may retain the associated inputs and outputs for up to 2 years". Source: Zero data retention, https://code.claude.com/docs/en/zero-data-retention (no date shown).
- "The new unified Claude experience isn't available to organizations with zero data retention." HIPAA-ready and CMEK organizations are also excluded (summary). Source: https://support.claude.com/en/articles/17444462-set-up-and-manage-the-new-unified-claude-experience-for-your-enterprise-organization.
- HIPAA (Enterprise, with a BAA) applies to "Claude Code (local mode) and Cowork (local mode)". Source: https://claude.com/docs/cowork/hipaa-setup.

### 4.4 Region and data residency

## Implications for Probanda's promises

These follow directly from the facts above.

- In a Cowork session on Pro, Max or Ultra started after October 6, 2026, the model and the agent loop run on Anthropic's servers. A promise that client information is processed only on the lawyer's computer is not true for that session. Any file content Claude reads, including through the desktop app, is processed on Anthropic's servers.
- A promise that client files never leave the lawyer's computer is not true when Claude reads them in a cloud session. A promise that the original files and folders stay on the lawyer's computer is consistent with the docs ("Your folders stay on your computer").
- A promise that Claude cannot reach folders the lawyer has not connected is consistent with the docs, and so is the statement that it cannot reach local files while Claude Desktop is closed.
- Session content, including fetched file copies, is stored in the lawyer's Claude account on Anthropic's servers until deleted, then removed from Anthropic's back end within 30 days. Flagged content can be kept up to 2 years. A promise of no storage at Anthropic is not true for Cowork cloud, Claude Code cloud sessions, Remote Control or artifacts.
- Whether client information can be used for training depends on the lawyer's plan and settings. On consumer plans (Pro, Max, Ultra), it is used if "Help improve our AI models" is on, kept de-identified up to 5 years, and feedback (thumbs up/down) is used regardless. On Team and Enterprise, Anthropic does not train on it unless the customer opts in, but feedback submissions may be used.
- ZDR does not cover Cowork, and it disables cloud sessions, Remote Control and artifacts. No plan offers zero retention for Cowork.
- Stored data is in the US, and inference may run in the US, Europe, Asia or Australia unless the organization is on usage-based Enterprise with US-only inference. No Canadian location is offered. This bears on the disclosure points in `2026-10-15_privacy-law-and-data-location.md`, section 2.
- An artifact holds whatever data Claude puts into the page, on Anthropic-operated infrastructure. It is private until shared and can be made public. It is not deleted automatically on consumer plans under any documented rule.
- Probanda's observed local-tool bridge is not described in Anthropic's docs, so no Anthropic document supports or rules out a promise about where those tool calls' results go.
