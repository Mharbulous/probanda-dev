# Plan: IMAP mail tools in the practice plugin's `data` server

Written 2026-10-15. Verified against HEAD `b8a4159c6`-era state of this repo (files named below were read in full unless a line range is given).

## Goal

Give the practice plugin's `data` server (`source/practice/mcp/`) its own IMAP mail tools, so a Cowork session reads the practitioner's mailbox through Probanda alone and the "iCloud (mail, calendar, contacts)" desktop extension is retired for mail. Mail reading plus one write, `save_draft` (IMAP APPEND to the Drafts folder). Host, port and username are configuration, with iCloud (`imap.mail.me.com:993`) as the documented example only.

## Scope

Authorized: `source/practice/mcp/` (src, test, package.json, package-lock.json, scripts/bundle.mjs), `.claude/skills/` files named in step 7, `source/practice/agents/delivery-checker.md`, the built `plugins/` output of `scripts/build_plugin.py`, and a `/release` of `practice`.

Out of bounds: SMTP or any send, reply or forward; move, flag, mark-read or create-folder tools (Superseded 2026-10-19: `mail__create_folder`, `mail__rename_folder` and `mail__move_messages` were added so the mailbox can be sorted; flag, mark-read, message delete and folder delete stay out, see Safety); calendar and contacts (the extension stays for those; `build-timeline/reference/ICloudCalendar.md` keeps its route) (Superseded 2026-10-15: calendar and contacts reading moved into the plugin, as the read-only `calendar__*` and `contacts__*` tools on the same credential. The extension stays only for the briefing send.); the CoClerk repo; the extension's own source; `COMMANDMENTS.md`; any tool name, server key or plugin name that already exists; the research and file-manager bundles (the `files` bundle shares the source but must not gain these tools: `buildFileManagerToolDefinitions()` is untouched).

## Decided by the owner (not reopened)

## Safety

- The only tool that changes the mailbox is `mail__save_draft`, and it only appends to a folder. No tool deletes, moves, copies, flags, marks read, creates a folder, or sends. Every read opens its mailbox with `readOnly: true`, so the server never sets `\Seen` as a side effect. `imapflow`'s `messageDelete`, `messageMove`, `messageCopy`, `messageFlagsAdd/Remove/Set`, `mailboxCreate/Delete/Rename` are never called; a unit test greps `src/mail/` for those names and fails on any hit (step 4 check). (Superseded 2026-10-19: three organizing writes were added. `mail__create_folder` calls `mailboxCreate`, and `mail__rename_folder` calls `mailboxRename` and refuses INBOX and every special-use folder. `mail__move_messages` opens its source folder writable, the one writable open, and moves only the named UIDs. It uses only the server's MOVE, and a server without MOVE is refused before anything changes, because imapflow's `messageMove` falls back to copy and expunge there. `messageCopy` and `messageDelete` are never called. No tool deletes a message or a folder, flags, marks read or expunges. The unit test now enforces each of these.)
- The password lives in `%LOCALAPPDATA%\Coclerk\mail\mail.json.dpapi`, DPAPI-protected, written with `protect` forced true. It is never logged (`logger: false` on every `ImapFlow`, and the pino shim), never returned by any tool, never included in an error message (error text is built from the server's `responseText` and the host/username only), and never written to `coclerk.json` or any skill file. `configure_status` reports `password_set: true/false` and nothing else about it.
- A call that cannot finish fails within the timeout with a structured error and the connection is closed, so no stuck socket outlives the call.
- `mail__download_attachment` writes only under the `save_dir` the caller names and never overwrites. `mail__save_draft` reads only the `.eml` named.
- No maintainer value ships: the only host string in source and skill text is the documented example `imap.mail.me.com`, and no address, username or `Users\...` path.

### Step 2. Connection helper with timeout

Files: new `src/mail/imap.ts`.

- `type ImapClientFactory = (credential: MailCredential) => ImapClientLike`, where `ImapClientLike` is the minimal interface the tools use (`connect`, `logout`, `close`, `list`, `status`, `mailboxOpen`, `fetch`, `fetchOne`, `search`, `download`, `append`, `mailbox`). The default factory builds `new ImapFlow({host, port, secure, auth: {user, pass}, logger: false, socketTimeout: 30_000, greetingTimeout: 15_000, connectionTimeout: 15_000})` and attaches a no-op `error` listener, as the extension did.
- `withImap(state, factory, fn, timeoutMs = 30_000)`: refuses with `DataServerError(..., "mail_not_configured")` when `state.credential` is null (message names `mail__configure_credential`, and carries `credentialError` when set); otherwise one connection per call: `connect()`, `fn(client)`, then `logout()` (falling back to `close()`), the whole thing raced against a timer. On timeout: `client.close()` and throw `DataServerError("mail: the IMAP server did not answer within 30 s (<what was being done>); the connection was closed. Retry once; if it fails again, report the mail server as unreachable.", "mail_timeout")`. On an authentication failure (imapflow sets `authenticationFailed`, or the message matches `/auth|credential|login/i`): `DataServerError(..., "mail_auth")` naming the host and username. The password never appears in any message. One connection per call is the "reconnect after a stall": nothing persists between calls to get stuck.
- `specialFolder(client, use, names)`, `sentFolder`, `draftsFolder`: as the extension's.

Check: covered by step 4's unit test (the timeout test uses a fake client whose `fetch` never resolves and a 50 ms timeout; it asserts the error code `mail_timeout` and that `close()` was called).

### Step 3. Body rendering

Files: new `src/mail/body.ts`; new `test/mail-body.unit.test.mjs`.

`renderBody(parts: MimeParts, opts: {format: "text" | "html"; maxLength: number; stripQuoted: boolean; stripInlineImages: boolean})` → `{body, bodyFormat, bodyTruncated?, strippedQuoted?, strippedInlineImages?}`:

- `text`: `parts.plain`, else `readHtml(parts.html).text`, else `""`. `html`: `parts.html`, else `parts.plain` HTML-escaped with `<br>`.
- `stripInlineImages`: in `html`, remove every `<img ...src="data:...">` tag; in `text`, remove every `data:image/<type>;base64,<base64 run>` substring. Count the removals in `strippedInlineImages`.
- `stripQuoted` (`text` only; in `html` it is applied to the text rendering, so set `format: "text"` when both are wanted and say so in the description): cut at the first line, after the first non-blank line, that starts a quoted reply: `/^On .{1,200} wrote:\s*$/`, `/^-{2,}\s*Original Message\s*-{2,}$/i`, `/^_{10,}$/`, `/^From: .+$/` followed within the next 4 lines by `/^(Sent|Date): /` and `/^To: /`, or the first run of two or more consecutive `> ` lines. Set `strippedQuoted: true` when something was cut. Trailing whitespace trimmed.
- Then truncate to `maxLength`, setting `bodyTruncated`.

Also export `summarize(message, folder)` (the extension's `summarize`, producing the search-result shape with `date` as ISO UTC) and `attachmentList(bodyStructure)` (walks imapflow's `bodyStructure`, listing every node with a `disposition` of `attachment` or a filename on a non-text type: `{index, part, filename, contentType, size, contentId, inline}`).

Check: `node --test test/mail-body.unit.test.mjs` passes. Fixtures are synthetic strings built in the test (no real mail): a reply chain with "On ... wrote:" and with "-----Original Message-----" and with an Outlook `From:/Sent:/To:` block, each asserting the body ends before the marker and `strippedQuoted` is true; a body with a `data:image/png;base64,...` run asserting it is gone and counted; defaults off leave the body untouched; truncation sets `bodyTruncated`; `summarize` emits `messageId` with angle brackets and omits `cc` when empty (the ingest contract); `attachmentList` on a hand-built two-part structure.

### Step 4. Tools, definitions, dispatch

Files: new `src/mail/tools.ts`; `src/schema-gen.ts` (new `mailToolDefinitions()` and its spread in `buildToolDefinitions()`, not in `buildFileManagerToolDefinitions()`); `src/dispatch.ts` (`DispatchContext` gains `mail: MailState` and `imapFactory?: ImapClientFactory`; `callTool` routes `name.startsWith("mail__")` to `callMailTool(context, name, args)`); `src/index.ts` (`createDispatchContext` awaits `loadMailConfig(env)`); new `test/mail-tools.unit.test.mjs`.

`tools.ts` ports the extension's handlers for the kept tools onto `withImap`, with:

- `configure_credential`: validate inputs (`host` non-empty, `port` an integer 1-65535, `username` and `password` non-empty printable strings), probe through the factory (`connect`, `status("INBOX", {messages: true, unseen: true})`, `logout`) under the same timeout, then set `state.credential` and persist; a failed persist returns `persisted: false` with the warning text the suggestion-box tool uses.

## Assumptions (for the orchestrator to put to Brahm)

1. **Input naming is snake_case** (`include_body`, `search_all_folders`), matching the server's other tools, while message outputs keep the extension's camelCase keys (`messageId`, `totalFound`) that `build_ingest.py` and SentMail.md depend on.
2. **`mail__save_draft` takes an existing `.eml` path** (from the `write_email` route) rather than compose fields, so no MIME composer is added and the roster From and signature rules in `shared/email.md` keep one owner. Compose fields (`to`, `subject`, `text`, attachments) are the alternative if Brahm wants a draft without first writing a file.
3. **One IMAP connection per call** is the stall recovery (nothing persists to get stuck), at the cost of a login per call (about a second on iCloud). A pooled connection with reconnect-on-error is the alternative; not chosen because the stall cause (spec open question 2) is unknown.
4. **Body formats are `text` and `html`; `markdown` is dropped** with turndown. `text` comes from the plain part or `readHtml`.
5. **Attachment download needs `save_dir`** (no default download folder, no inline image content). The extension's `Downloads\icloud-attachments` default and inline image return are dropped.
6. **Full message source is fetched for a body read** (as the extension did) and parsed by `eml.ts`; a message with large attachments costs its full size per read. The 25-message cap on `include_body` is kept. Fetching only text parts by `bodyStructure` is the optimisation if this proves slow.
7. **The credential file holds host, port, secure, username, from_address and the password together** in one DPAPI file (`%LOCALAPPDATA%\Coclerk\mail\mail.json.dpapi`), so one tool configures everything. Only the password is secret, but keeping the non-secret fields in the same file is simpler than a second plaintext file.
8. **`date` is ISO 8601 UTC** (`toISOString()`), not formatted in a configured timezone; SentMail.md already converts.
9. **Timeout 30 s per call**, overridable for tests only.
