# Token-efficiency findings for /ingest and /housekeeping

Written 2026-10-19 for map #100 ticket #149, as the findings report named under "Analysis and the decision it feeds" in [the protocol](2026-10-17_token-efficiency-test-protocol.md). The protocol holds every measurement; this report states the decisions and the figures they rest on. Brahm approved it on 2026-10-19. Changing the skills is the spec this report hands to.

Scope: every run was in Cowork, on Opus, Sonnet and Haiku 5.5, against 12 keyed documents (598 gold facts, 12 names) and a 66-document corpus. Whether the results hold in the Code tab was not measured: the same API and prices apply and the decisions are relative, so they are assumed to hold. Email quoted-history stripping is left to the spec, because relying on each earlier message being ingested on its own would change the extraction protocol's rule against merging facts across sources. Measured spend was about $93 of the $150 budget, plus the unmeasured items the protocol's gates list.

## Decisions

| Question | Decision | Rests on | Spread (Q17) |
|---|---|---|---|
| Q9, Q13: /ingest extractor model and effort | `extract-facts` runs on **Opus at high effort**, set explicitly rather than inherited from the session. Apply the same to `extract-affidavit`, which has the same fact contract. `extract-caselaw` was not measured. | E7: recall 0.83 at about $0.36 a document, against Opus medium's 0.74 at $0.28, Sonnet high's 0.67 at $0.17–0.22 and Haiku high's 0.58 at $0.02 with wrong and reversed claims. Recall under a blind Fable scorer (#148). | One run per cell. Opus medium varied up to 37 points on one document across 3 repeats. The key began as an Opus-high extraction, which may favour Opus high. |
| Q1: shared against separate context | Housekeeping naming runs **apart from extraction**. No crossover was found at any size or format. | E5, E2: naming in the extractor's Opus context cost $0.36 a document and got 7 of 12 names right on all four structured parts; a separate Haiku pair from page 1 cost $0.0084 and got 8. | One run per cell; E5-B's same design got 5. |
| Q10, Q9: housekeeping pages and model | A **Haiku** reader reads **page 1 only**, and `housekeeping-namer` runs on **Haiku** (its pin changes from `sonnet`). Names still pass the approval page. | E2: Haiku 8 of 12 at $0.0084, Sonnet 9 at $0.098. At 2 and 5 pages names got worse on both models, as the reader named enclosures and quoted messages. | One run per cell. The namer is about 80% of each document's cost, mostly the naming references, so a namer batch of about 15 (the agent's current design) should cost less per document than measured. |
| Q2–Q5: pages per subagent | **One extractor per document**, reading **20 pages at a time**, for OCR PDF, scanned PDF, .docx and .msg alike. Do not batch small documents together, and do not split long ones into chunk extractors. | E3: batching to 20 pages moved cost −13% to +13% with no recall gain; 40 pages lost 5–10 points. Chunks cost 1.4–2× for no clear gain. 5-page reads cost 5–10% more. Cost is about $0.02–0.04 a run plus about $0.005–0.006 per page and per fact extracted, so it follows facts more than pages, and format matters little. | Tested to 54 pages. .msg only to 20 pages, because no longer email was in the corpus. |
| Q11, Q16: input format | Read OCR and scanned PDFs **natively**. Drop `ingest-extract`'s ~150 DPI pre-render of scanned affidavit pages. Keep an email's attachments in the same extractor. | E4: native reads scans at about 100 dpi; 150 dpi cost 21–51% more with no recall gain. A text layer saved nothing and caused the only garbled fact. A separate attachment extractor changed nothing. | One run per cell. E4 used `extract-facts`, so the spec should confirm the affidavit change on one affidavit. |
| Q6–Q8: reusing the fixed cost | A **fresh extractor per document**, launched in parallel waves less than 5 minutes apart. No SendMessage resume, no fork. | E1: siblings share the ~9k-token cached prefix ($0.046 cold, $0.012 warm on Opus), in parallel or in sequence, while the 5-minute TTL holds. E6: a resume saved −$0.017 to +$0.006 and once lost 2 of 7 facts. A fork reads the parent's ~150k-token context. Rewind does not exist. | 3 of 3 reps on caching; 3 resume pairs. |
| Return format | `extract-facts` **writes its result to a file**, and a new `matter_data` tool loads the fact rows from it, as `ingest_authority` does for `extract-caselaw`'s `RESULT_PATH`. Without that tool the file route saves nothing, because the orchestrator would rewrite every fact as SQL. | #147: a full reply (mean 6.1k tokens) costs $0.04–0.14 a document to carry, $1.14–4.18 for 30 documents, which is 14–50% on top of extraction, against about $0.03 for 30 by file. It also keeps about 182k tokens out of the orchestrator's context. | Priced from 34 Opus-medium replies; the real /ingest turn count is an estimate. |
| Q12: output share and compact JSON | Keep the current JSON contract. | E3, E8: output is 39–89% of an extraction's cost, mostly the facts' own sentences and thinking. Compact JSON saved about 4%. | Inside run-to-run spread. |

## Other findings

- **Orchestrator cost (Q14).** A Sonnet test orchestrator cost $1.05–3.58 a session, often as much as its subagents. It writes its cache at the 1-hour price. The file-return decision above is the measured lever on it.
- **Extraction cost per document.** Opus medium averaged $0.279 over 34 whole documents; a 1-page document still costs $0.04–0.11.
- **Scorer cost.** A future scorer subagent should be an agent type holding only Read. The `general-purpose` scorers in #148 loaded about 94K tokens of tool definitions each and cost $19.7 for 15 runs.
