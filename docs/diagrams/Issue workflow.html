What is supposed to happen to a probanda-dev issue

Every issue passes through triage, which labels its state and where the work can run. A label then decides who works on it next.

The queue stops only when no issues are left, when only issues needing a person are left, when only local issues are left while the PC is unavailable, or for a mix of the last two.

How an issue or a start begins Runs in the cloud, unattended Runs on Brahm's PC, unattended Needs Brahm Finished Parked or left alone

The commit tag cannot pin things outside the repo. Those are the cloud routines' schedules and event wiring, and the tasks registered on the PC. The event routes in Diagram 1 rest on docs/agents/issue-tracker.md, not on a read of that wiring.
