# Terminology Crosswalk

> This file is updated whenever schema anchors change. It maps each case-data term in the root `GLOSSARY.md` to its exact table/column/view/CHECK-value anchor in the v7.0 schema (`schema.sql`, `queries.sql`). The root `GLOSSARY.md` points here rather than embedding table names in glossary prose — if a table or column is renamed, update this file only.

| Term | Schema anchor | Notes |
|---|---|---|
| Matter | `main.matter_metadata` (key/value) | Self-describing identity table, not a dedicated `matters` table. Keys are seeded by `operations/initialize.md` and audited by `operations/profile.md`. |
| Matter reference | `main.matter_metadata` key `matter_id` | The **key name is historical and is not renamed**; its *value* is the matter folder's leading token (`8575.L8443` or `L8470`), parsed by `references/scripts/resolve_paths.py::parse_folder_name`. The same value names the case-data folder (`0. CASE DATA\<matter_id> <short_name>\`, `../shared/conventions.md` §2.1) and binds an application (`applications.matter_id` in the separate application schema). |
| Matter number | `main.matter_metadata` key `matter_no` | Copied at initialize from the practice database's `matt_num` (`L8443`), obtained through the `/practice-data` gatekeeper. Equal to the matter reference whenever the matter folder is named by the matter alone; never derived from it. |
| Matter row key (practice database) | The `id` of a matter item in the practice database, returned as `matter_id` on the practice items linked to that matter | Outside this schema entirely — recorded here only because the name `matter_id` means something *different* there: an internal generated item ID, never displayed. Owned by `/practice-data`. |
| Proceeding | `main.proceedings` | Columns: `proceeding_id`, `court`, `registry`, `file_number` (UNIQUE), `style_of_cause`, `courthouse_address`, `trial_date`, `status`. |
| Proceeding.status | `main.proceedings.status` CHECK(`active`\|`stayed`\|`concluded`) | Lifecycle status of a proceeding — distinct from Fact Posture, which is never stored. |
| Party | `main.parties` | `party_id`, `name`, `party_type` CHECK(`individual`\|`corporation`\|`partnership`\|`other`). |
| Party role (in a proceeding) | `main.proceeding_parties.role` CHECK(`plaintiff`\|`defendant`\|`third_party`\|`intervenor`\|`applicant`\|`respondent`\|`petitioner`\|`appellant`\|`defendant_by_counterclaim`) | Junction table `proceeding_parties(proceeding_id, party_id, role)`. `appellant` is the BC Court of Appeal's moving-party role; `respondent` is reused unchanged for the opposing party there, as it already is for a petition or an application. `defendant_by_counterclaim` is standalone only; exactly `{defendant, third_party}` is the sole valid stack. |
| Tribunal member | `main.tribunal_members` | `tribunal_member_id`, `name`, `capacity` (free text, the forum's word), `tribunal_body` (the forum), `proceeding_id` (nullable), `notes`. v9.0, decision #65. |
| Alias / file code | `main.participant_aliases` | `alias_text`, `alias_kind` CHECK(`spelling`\|`file_code`), `approved_on` (NOT NULL), and exactly one owner: `party_id` (with `of_counsel` 1 for the party's counsel), `witness_id` or `tribunal_member_id`. Unique per owner, case-insensitively. v9.0, decision #65. |
| Source | `main.sources` | `source_id`, `title`, `file_path`, `file_hash`, `date`, `notes`. |
| Source.category (storage) | `main.sources.category` CHECK(`court`\|`correspondence`\|`production`\|`work_product`\|`disbursements`) | Storage-side enum. Distinct from the routing-category enum used in subagent JSON output (`shared/extraction-protocol.md`), which additionally includes `privileged`, `authority`, `other` as routing-only values never written to this CHECK. |
| Authority | `law.authorities` | `authority_id`, `title`, `citation`, `authority_type`, `jurisdiction`, `disposition`. Zero client data — separate database. |
| Authority.authority_type | `law.authorities.authority_type` CHECK(`case_law`\|`statute`\|`regulation`\|`treatise`\|`other`) | |
| Privileged Source | `privileged.privileged_sources` | `source_id`, `proceeding_id` (trigger-FK to `main.proceedings`), `title`, `file_path`, `file_hash`. Lives in the physically separate `privileged.sqlite` database. |
| Privileged Source.category | `privileged.privileged_sources.category` CHECK(`solicitor_client`\|`privileged_correspondence`\|`privileged_work_product`\|`other`) | |
| Fact | `main.facts` | `fact_id`, `description`, `category`, `date_of_fact`, `source_id`, `source_locator`. |
| Fact.category (soft vocabulary) | `main.facts.category` (no CHECK constraint) | Soft vocabulary used by extractors: `background\|contract\|payment\|breach\|employment\|damages\|procedure\|liability\|credibility` — kept consistent by convention, not enforced by schema. |
| Provenance | `privileged.fact_provenance` | `fact_id` (trigger-FK to `main.facts`), `source_id` (FK to `privileged_sources`), `source_locator`, `source_note`, `disposition`. Investigative provenance — never conflated with `evidence_links`. |
| Bare Row | `main.facts` row with `description = ''` and every other content column NULL or 0 (`operations/bare-privileged-facts.md` §1) | A Fact known only through privileged sources (#67). Its Statement of Fact is on the labelled `STATEMENT:` line of `privileged.fact_provenance.source_note` (§2). Skipped by `v_fact_status`, `@query_05a` and `@query_05b`; shown only by `@query_10` and `@query_22`. |
| Theorized Fact | `main.facts` bare row (`source_id IS NULL`) + `privileged.fact_provenance` linked to a `privileged_sources` row where `category = 'privileged_work_product'` AND `title LIKE 'Theory of the case —%'`, with no `evidence_links` | Not a position, not a posture — provenance only. Surfaced by `@query_22_theorized_facts`. The *Theory of the case — <app-id>* placeholder source is one per application, created lazily by `operations/theorize-fact.md`. |
| Dismissed (theorized-fact disposition) | `privileged.fact_provenance.disposition` CHECK(`active`\|`dismissed`) DEFAULT `active` (v7.4) | Terminal investigation disposition; set by `operations/theorize-fact.md` dismiss path, never by delete. Distinct from `proceedings.status` and `issues.status`; unknowable for the opposing side. |
| Evidence (link) | `main.evidence_links` | `evidence_link_id`, `source_id`, `fact_id`, `source_locator`, `strength` CHECK(-2..2), bitemporal (`valid_from`, `valid_to`, `prior_id`). |
| Proof | *(no direct schema anchor — a judgment, not a stored value)* | Evidenced indirectly via `evidence_links.strength > 0`, admissions in `positions`, or agreed-fact posture from `v_fact_status`. |
| Position | `main.positions` | `position_id`, `fact_id`, `party_id`, `position`, `qualification`, bitemporal (`valid_from`, `valid_to`, `prior_id`). |
| Position value | `main.positions.position` CHECK(`claim`\|`admit`\|`deny`\|`not_admit`\|`no_position`) | Actual silence is no row. "No knowledge" is `not_admit/outside_knowledge`; verbatim limiting wording goes in `qualification`. |
| Qualified admission | `main.positions.position = 'admit'` + `main.positions.qualification` (verbatim text) | One row only — never split into admit + deny rows. |
| Fact Posture | `main.v_fact_status.posture` (view, derived column) | Values: `disputed`\|`admitted`\|`not_admitted`\|`no_position`\|`claimed`\|`unaddressed`. Computed from `main.v_current_positions`; never stored on `facts`. |
| Current positions (view) | `main.v_current_positions` | `WHERE valid_to IS NULL AND verified >= 0 AND pending_reverification = 0`. |
| Issue | `main.issues` | `issue_id`, `title`, `description`, `issue_type`, `status`, `priority`. |
| Issue.issue_type | `main.issues.issue_type` CHECK(`factual`\|`lawyer`\|`mixed`) | Question of fact / law / mixed fact and law. |
| Issue.status (lifecycle) | `main.issues.status` CHECK(`open`\|`resolved`\|`abandoned`) | Lifecycle status of the issue itself — distinct from Fact Posture. |
| Legal Concept | `law.legal_concepts` | `concept_id`, `name`, `concept_type`, `jurisdiction`, `in_force_date`, `repeal_date`. UNIQUE(name, jurisdiction). |
| Legal Concept type (5 kinds in one table) | `law.legal_concepts.concept_type` CHECK(`cause_of_action`\|`doctrine`\|`test`\|`defence`\|`remedy`) | Discriminator — never split into separate tables. |
| Element | `law.legal_criteria.requirement_type = 'element'` | Mandatory — a gap here is FATAL in gap analysis (`@query_03_coa_gap_analysis`). |
| Factor | `law.legal_criteria.requirement_type = 'factor'` | Weighed — a gap here is WEAK ("WEAK (factor gap)" in `@query_03_coa_gap_analysis`). |
| Cause of Action Concept | `law.legal_concepts` where `concept_type = 'cause_of_action'` | General law, no client data. |
| Asserted Cause of Action | `main.causes_of_action` | `coa_id`, `proceeding_id`, `claiming_party_id`, `against_party_id`, `name`, `concept_id` (trigger-FK to `law.legal_concepts`). Case-specific instance vs. the general concept. |
| Coa criterion sufficiency | `main.coa_criteria.sufficiency` CHECK(`proven`\|`likely`\|`gap`\|`unknown`) | Case-specific assessment of a criterion for one asserted cause of action. |
| Verified (enum, all `verified` columns) | `main.sources.verified`, `main.facts.verified`, `main.positions.verified`, `main.evidence_links.verified`, `main.issues.verified`, `privileged.privileged_sources.verified`, `privileged.fact_provenance.verified` — all CHECK(`-1`\|`0`\|`1`\|`2`) | `0` unverified, `1` verified (AI or lawyer), `-1` rejected, `2` needs human judgment. Quality-of-extraction flag — never a truth/proof flag. |
| Human-reviewed flag | `main.facts.human_reviewed`, `main.positions.human_reviewed` CHECK(0\|1) | Distinguishes lawyer-confirmed from AI-verified; only the review operation sets it to 1. |
| Pending re-verification quarantine | `main.facts.pending_reverification`, `main.positions.pending_reverification` CHECK(0\|1) | `1` marks an auto-corrected row awaiting a fresh isolated second pass. It may coexist only with `verified = 0` and `human_reviewed = 0`; it is excluded from ordinary factual consumers and the ordinary AI backlog. |
| Source Citation (computed) | Derived from `sources.file_path` + `facts.source_locator` / `positions.source_locator` / `evidence_links.source_locator` | Display form `<file_path>#<locator>`; never stored as a combined column. |
| Legal Citation (reported) | `law.authorities.citation` | Reported case/statute citation, recorded as-is (not computed). |
| Authority relationship to a concept (present tense) | `law.concept_authorities.relationship` | What the authority does for the concept. Every value and its definition: `../../shared/treatment-vocabulary.md` (design: `docs/Specs/2026-10-15_per-principle-treatment-vocabulary-spec.md`). Treatment is recorded per concept, not per case. |
| Authority treatment (present tense, authority-to-authority) | `law.authority_treatments.treatment` CHECK(`affirms`\|`reverses`\|`varies`\|`distinguishes`\|`overrules`) | Models appellate history between two `authorities` rows. |
| Proposition-level treatment (past tense) | `law.concept_authorities.treatment`, `law.legal_criteria.treatment` CHECK(`affirmed`\|`reversed`\|`varied`\|`distinguished`\|`overruled`) | Applied to the treated authority's linked propositions/criteria, distinct from the authority-level present-tense value above. |
| Criterion nesting (one hop) | `law.legal_criteria.determined_by_concept_id` (FK to `law.legal_concepts`) | An element/factor determined by a test concept; soft convention that the target has `concept_type = 'test'`. See `@query_15_element_test_hierarchy`. |
| Compound document parent/child | `main.sources.parent_source_id` (self-referential FK to `main.sources`) | Body row has `parent_source_id IS NULL`; exhibit rows point to the body. |
| Basis of knowledge | `main.facts.basis_of_knowledge` CHECK(`personal`\|`information_and_belief`), `main.facts.informant` | Affidavit hearsay tracking; privileged informant is NULLed in main and recorded in `privileged.fact_provenance.source_note`. |
| Ingestion status | `main.sources.ingestion_status` CHECK(`complete`\|`partial`\|`failed`) | Completeness signal, distinct from `verified`. |
| Review queue | `main.review_queue` (view) | Facts with `verified = 2 AND human_reviewed = 0`, plus sources with `verified = 2 OR ingestion_status = 'failed'`; `flag_type` derived from `notes` prefix. |
| Notes prefixes | `main.facts.notes` / `main.positions.notes` / `main.sources.notes` free text, prefixes `DISCREPANCY:` \| `UNCONFIRMED:` \| `OCR:` \| `REVERIFICATION:` | Machine-detectable annotations recognized by `review_queue.flag_type` and the review protocol. `REVERIFICATION:` identifies a targeted second-pass adverse finding. |
| Bitemporal pattern | `main.positions` (`valid_from`, `valid_to`, `prior_id`), `main.evidence_links` (`valid_from`, `valid_to`, `prior_id`) | Current row has `valid_to IS NULL`; supersession inserts a new row referencing the old as `prior_id`. |
