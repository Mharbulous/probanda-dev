# Probanda plugin repository

This repo is a publish target, not a workshop. `plugins/probanda/` is generated by `scripts/import_from_coclerk.py` from CoClerk's packaged `litigation` and `legal-commons` plugins, and is never edited by hand here. To change the plugin, change the source in CoClerk, repackage there, then re-run `python scripts/import_from_coclerk.py --coclerk <CoClerk checkout>` and commit the result. Only `.claude-plugin/marketplace.json` and the repo docs (this file, the READMEs, `scripts/`, `.github/`) are maintained here.

## The move from CoClerk (two phases)

- **Phase 1 (now):** CoClerk stays the source of truth and keeps its own `litigation` and `legal-commons` plugins. The import script renames every identifier to `probanda` and merges legal-commons' read side only: its gatekeeper skill, the `law-librarian` and `troubleshooter` agents, and its MCP server under the key `commons`. The push skills (`consolidation-push`, `rule-sharing`) stay in CoClerk, and `hooks/commons-read-only.py` refuses the commons write tools. A few shipped files still mention those two skills; they are not available in Probanda.
- **Phase 2 (after Probanda is installed and working):** move the skill sources here, then repoint CoClerk's global-skills setup, `litigation-codex` and the packager.

## Permanent names

These are permanent once published. Do not rename them.

- The plugin name `probanda`.
- The marketplace name `probanda`.
- Every MCP server key in a plugin's `.mcp.json`.

Together they make up the tool names (`mcp__plugin_probanda_<server>__*`), the install key (`probanda@probanda`) and the `${CLAUDE_PLUGIN_DATA}` directory. A rename strands every user's installed copy and saved data. `displayName` and descriptions can change freely.

## Cowork constraints

Cowork runs plugins in a sandboxed Linux VM.

- Every path in `.mcp.json`, hooks and scripts uses `${CLAUDE_PLUGIN_ROOT}` or `${CLAUDE_PLUGIN_DATA}`, never an absolute path.
- MCP servers ship as self-contained bundles with no install step at runtime.
- Scripts use LF line endings and are executable.
- A plugin has no top-level `bin/` directory, because Cowork does not install a plugin that has one.

## Never commit

- SQL files or schema DDL. **Phase 1 exception:** `plugins/probanda/` still ships the legacy schemas (`.sql` files in its data skills, and DDL in the data server bundle), so the publish-readiness check fails by design until the schema-split rebuild removes them. Nothing outside `plugins/probanda/` may add any.
- Databases.
- Built `.plugin` archives.
- Handovers or E2E reports.
- Client or matter data.
- Secrets.
- File paths from the maintainer's machines.

`scripts/check_publishable.py` enforces this and also pins the permitted plugin and marketplace names. CI runs it on every push and pull request. Run it locally with `python scripts/check_publishable.py` before committing.

The repo must never be made public while this check fails on `main`.
